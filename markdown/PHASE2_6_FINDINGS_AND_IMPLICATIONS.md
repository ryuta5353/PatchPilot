# Phase 2-6 Greedy Allocation 実行結果: 重要な発見と含意

**分析対象**: 20インスタンスの Greedy allocation デバッグデータ
**主な観察**: トークン予算内達成 vs 性能改善の分断

---

## この結果から考えられること（5つの重要な発見）

### 1. **Greedy Allocation は「正常に機能」しているが、問題がある可能性**

**データ**:
- 平均 16,277 トークン使用 (52.9% of budget)
- 前回 33,313 トークン (超過)
- 削減率: 51.1%

**考察**:
```
前の実装: トークン予算を超過 → Greedy allocationなし状態
現在の実装: トークン予算内 → Greedy allocationが機能

BUT: 次の疑問が生じる
  Q1: 平均 16,277 は適切か？それとも削減しすぎ？
  Q2: タグが削減されることで、ラインレベル精度が悪化していないか？
  Q3: グラフコンテキストの質が低下していないか？
```

**含意**: Greedy allocationが「トークン予算内」を達成しても、
「性能向上」に繋がるとは限らない。

---

### 2. **インスタンスごとのトークン使用差が大きい（3倍～100倍）**

**観察**:
```
最小: django__django-14534   = 2,599 tokens (8.4%)
最大: astropy__astropy-14182 = 30,494 tokens (99.2%)

比率: 30,494 / 2,599 = 11.7倍の差
```

**セクション数の差も大きい**:
```
少ない: django__django-14534   = 6 sections added
多い:   sympy__sympy-13031      = 8 sections added
        pytest-dev__pytest-7490 = 12 sections added

最多:   sphinx-doc__sphinx-8595 = 14 sections added
```

**重要な疑問**:
- なぜインスタンスごとにこんなに差が出るのか？
- グラフサイズの差か？ リポジトリ規模か？
- これが性能（ファイル/ラインレベル）に影響しているか？

---

### 3. **セクションスキップが少ない（11/111 = 9.9%）**

**観察**:
```
Total sections processed: 111
Sections added: 100 (90.1%)
Sections skipped: 11 (9.9%)

セクションスキップが発生したインスタンス:
  - astropy__astropy-14182: 2 skipped (予算内にする必要あり)
  - pydata__xarray-4094: 2 skipped
  - scikit-learn__scikit-learn-10297: 1 skipped
  - scikit-learn__scikit-learn-13496: 2 skipped
  - sympy__sympy-13031: 1 skipped
```

**含意**:
- Greedy allocationが「セクション追加」を優先している
- ほぼ90%のセクションが含まれている
- つまり、グラフコンテキストは「ほぼ完全」な状態

**問題点**:
- 完全なグラフコンテキストが本当に必要か？
- 削減されたタグは本当に重要ではないのか？
- 多くのセクション = ノイズ増加につながらないか？

---

### 4. **極限まで予算を使用するインスタンス（> 95%）が4個**

**観察**:
```
予算内での効率利用:
  astropy__astropy-14182:    30,494/30,740 (99.2%) ← 限界まで使用
  sympy__sympy-13031:        29,781/30,740 (96.8%)
  matplotlib__matplotlib-24970: 28,821/30,740 (93.8%)
  pydata__xarray-4094:       28,524/30,740 (92.8%)
```

**重要な気づき**:
これらのインスタンスでは、Greedy allocationが最も効果的に動作している。
セクション/タグ削減をしながら予算内に収める。

**問題**:
- 他のインスタンスはなぜ50%程度しか使用していないか？
- 低使用率インスタンスでは、グラフが十分ではないのか？

---

### 5. **「トークン削減」が必ずしも「性能改善」に繋がらない可能性**

**論理**:
```
Phase 2-6初期評価（前の実験）:
  - 平均トークン: 33.3K（超過）
  - ファイルレベル改善: +5.3pp ✓
  - ラインレベル悪化: -8.5pp ✗

現在の実装（20インスタンス）:
  - 平均トークン: 16.3K（削減）
  - ファイル/ラインレベル: 未評価

仮説：
  トークン削減 ≠ 性能改善
  むしろ、グラフサイズ削減 → ノイズ減少 → ラインレベル改善？
  または、重要なタグ削減 → 精度低下？
```

## 最終的な考察

### **Greedy Allocation は「トークン管理」には成功**

✓ 予算内達成 100%
✓ 効果的なセクション追加/スキップ
✓ 動的な予算配分

### **しかし、「性能向上」は未確認**

❓ ファイルレベルは改善するか？
❓ ラインレベルはどうなるか？
❓ 削減されたタグの影響は？

### **グラフコンテキストの「質」を再考すべき**

現在の Greedy allocation は「量」（トークン数）を管理していますが、
「質」（どのタグを含めるか）については optimize されていません。

例：
- 同じ 16K tokens でも、タグの「重要度」が異なる可能性
- Composite score はファイル関連性を優先（質に影響）
- ライン精度の向上には別のアプローチが必要な可能性

---
