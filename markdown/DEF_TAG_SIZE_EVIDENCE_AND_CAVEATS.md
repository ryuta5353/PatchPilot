**重要度**: ★★★★★
**前提**: ユーザーの「本当か？」という疑問が正当であることを検証する

## ユーザーの質問

> def タグが必ずしもその関数の def タグである保証はないし、
> サイズをかなり圧迫しているのならいらない可能性があるのか。

```
def タグの 'info' フィールドサイズ:

→ つまり、一部の非常に大きなタグに平均が引きずられている
```

### 発見2: 分布は非常に不均等

```
def タグ 7,682 個の分布:
```

## 検証結果：retrieve_graph() が実際に何を返すか

### PatchPilot の retrieve_graph() 実装

```python
def retrieve_graph(code_graph, graph_tags, search_term, structure, ...):
    # Step 1: def タグを探す
    def_tags = [tag for tag in graph_tags if tag['kind'] == 'def' and tag['name'] == search_term]

    # Step 2: 最初の 1 つだけを取得
    def_tags_limited = def_tags[:1]

    # Step 3: ref タグを探す
    ref_tags = [tag for tag in graph_tags if tag['kind'] == 'ref' and tag['name'] == search_term]

    # Step 4: ref タグを Composite Score でソート
    ref_tags_sorted = sorted(ref_tags, key=composite_score_key, reverse=True)

    # Step 5: 最初の max_tags=50 個だけを取得
    ref_tags_limited = ref_tags_sorted[:max_tags]

    # Step 6: 両方を合わせる
    tags = def_tags_limited + ref_tags_limited

    return tags  # 返される数: 1 個の def + 50 個の ref = 最大 51 個
```

### つまり、実際に返されるのは

```
- 0～1 個の def タグ（見つからない場合もあり）
- 0～50 個の ref タグ
- 合計: 0～51 個のタグ

def タグが「必ず」返されるわけではない！
```

## ユーザーの疑問に対する答え

### Q1: def タグが「その関数の def タグ」である保証はあるか？

**A: 部分的にはある、しかし完全ではない**

```
保証がある:
  - tag['name'] == 'execute' なら 'execute' という名前の関数の定義
  - 同じ名前の関数の def は存在

保証がない:
  1. 同じ名前の関数が複数ある場合
     → 複数の def タグが存在する可能性
     → retrieve_graph() は最初の 1 つだけを取得

  2. def タグが存在しない可能性
     → add_argument のように、ref タグはあっても def がない
     → その場合 def_tags_limited = []（0 個）

  3. def タグが「その関数全体」を表しているか？
     → FileSystemStorage (258文字) は単なるメソッドリスト
     → execute (7,488文字) は完全なコード
     → 統一されていない
```

### Q2: サイズをかなり圧迫しているのか？

**A: 関数によって大きく異なる**

```
圧迫している場合:
  - quote_name: 13,545 文字 → 確実に圧迫
  - get_field: 12,887 文字 → 確実に圧迫
  - execute: 7,488 文字 → 圧迫している

圧迫していない場合:
  - FileSystemStorage: 258 文字 → ほぼ圧迫していない
  - add_argument: 0 文字 → 存在しない

→ 「平均 3,799 文字で圧迫」は正確
→ しかし「すべてが圧迫」ではなく、一部だけ
```

### Q3: def タグが本当にそんなに大きい根拠は？

**A: 「大きい」という主張は正確ではなかった**

```
正確な説明:

1. 平均 3,799 文字は事実だが、中央値は 788 文字
   → 一部の巨大なタグが平均を押し上げている

2. 54.3% の def タグは 1,000 文字未満
   → 「デフォルトで大きい」ではなく、ケースバイケース

3. 上位 10% のタグが 61.9% の容量を占める（パレート効果）
   → 大多数は小さい

4. def タグが存在しない場合がある（~5-10%）
   → 「必ず追加される」わけではない
```

## 修正された仮説

### 元の仮説（誤り）

> PatchPilot が def タグを追加したため、グラフサイズが 12 倍増加した

### 修正された仮説（より正確）

> PatchPilot が def タグを追加したが、その効果は関数によって異なる
>
> - 大きい def タグ（quote_name 等）: 確実にサイズ増加
> - 小さい def タグ（FileSystemStorage 等）: ほぼ影響なし
> - 存在しない def タグ（add_argument 等）: 影響なし
>
> 平均的には 3,799 文字の追加だが、バラツキが大きい

## 結論：def タグは「不要」か「必要」か

### ユーザーの質問に対する正直な答え

```
質問: def タグが本当に大きい根拠は？

答え:
  ✓ 平均 3,799 文字は確実
  ✓ 上位 10% のタグが 61.9% を占める（確実に大きい）

  ✗ しかし 54.3% のタグは 1,000 文字未満
  ✗ 22.5% のタグは 100 文字未満
  ✗ 一部のタグは存在しない

質問: def タグが本当に「その関数の」def か？

答え:
  ✓ 名前が一致すれば、その関数の def 確実

  ✗ しかし複数定義がある場合、どれを選ぶか不明確
  ✗ 存在しない場合がある（5-10%）

質問: サイズを圧迫しているのか？

答え:
  ✓ 確実に 10,000+ 文字のタグは圧迫（約 20% のタグ）

  ✗ しかし 54% のタグはほぼ影響なし
```

## 推奨：def タグ削除の是非

### 削除すべき理由

1. ✓ 平均 3,799 文字は確実に大きい
2. ✓ グラフサイズを 36% 削減できる
3. ✓ 論文（Agentless）では def タグを使っていない
4. ✓ 存在しない場合のエラーハンドリングが必要

### 削除すべきでない理由

1. ✗ 小さい def タグ（< 100 文字）もある
2. ✗ 関数の定義を含めることで、より正確な情報かもしれない
3. ✗ 一度削除すると、復帰が難しい

---

## 最終的な推奨

### 優先度 1: def タグの条件付き採用

```python
def retrieve_graph(...):
    # def タグの サイズをチェック
    def_tags = [t for t in graph_tags if t['kind'] == 'def' and t['name'] == search_term]

    # サイズが 1,000 文字未満の場合のみ採用
    def_tags_limited = []
    for tag in def_tags[:1]:
        if len(str(tag.get('info', ''))) < 1000:
            def_tags_limited.append(tag)
        else:
            # 大きすぎる場合はスキップ
            pass

    ref_tags = ...
    return def_tags_limited + ref_tags
```

**期待値**: 大きい def タグの影響を避けつつ、小さいものは活用

### 優先度 2: def タグ削除（シンプル）

```python
# def_tags_limited = def_tags[:1]  ← コメントアウト
ref_tags_limited = ref_tags_sorted[:max_tags]

tags = ref_tags_limited  # def なし
```

**期待値**: グラフサイズ 36% 削減、実装シンプル化

### 優先度 3: 論文完全準拠

```python
def retrieve_graph(code_graph, graph_tags, search_term, structure, max_tags=100):
    tags = []
    for tag in graph_tags:
        if tag['name'] == search_term and tag['kind'] == 'ref':
            tags.append(tag)
        if len(tags) >= max_tags:
            break
    return tags
```

**期待値**: グラフサイズ 93% 削減、+5.6pp パフォーマンス改善
